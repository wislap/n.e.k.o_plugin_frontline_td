# 0030. 物流实现约定：付费方、道路倍率、走廊拦截与拓扑增量失效

- 状态：已采纳
- 实现：已实现
- 日期：2026-11-17
- 决策者：wislap
- 批次：M3 跨模块参考实现
- 领域：物流
- 部分取代：0025（连线沿道路走、倍率按长度加权）

## 背景

[ADR 0025](0025-logistics-model.md) 定了模型（车按需调度、配额、
自动路由）。M3 落地时对若干实现细节做了取舍，并新增道路升级
与走廊拦截两个机制。本文档细化 0025 而不改它：模型不变，约定
代码层的精确语义。

## 决策

### 付费与分配

- **付费方**：一条线路的两个方向各由一端节点付费——出库方向
  由离仓库更近的一端付，入库方向由更远的一端付；末段运距由
  被挂靠的节点付。一条线路的运力 = 沿途各付费方 `qMax` 的
  最小值，不做全局线性规划。
- 付费节点每周期有"车辆时间"预算 R。运 q milli 货物经长 L 的
  线路花费 `T(q) = ceil(2·L·q·10000 / (load·m))`；剩余预算
  能运的量 `qMax(R, L, load, m) = floor(R·load·m / (2·L·10000))`
  （load = 每车载量，m = 线路有效倍率，10000 是 bp 换算常量，
  全部整数运算）。
- 分配每个结算周期（`cycleTicks` = 1 秒）贪心执行：预算树每
  周期每方向各一棵并缓存，仅当某个付费节点预算归零才重建
  （与逐次重建逐位一致，有测试覆盖）。线路利用率按**实际付费方**
  的全额预算折算记账；瓶颈 = 预算最短的付费路径上第一个耗尽
  的付费方。
- `since` 存 `tick + 1`，0 表示"无"；export 槽同样记 unmet 原因
  码，快照通道把 unmet（需求）与 unmetExport（回收）分开统计。
- 建造中的实体只对 `SLOT_SITE` 槽产生需求（工地槽）；非
  `UnderConstruction` 实体行为不变——拆除中的建筑没有 SITE
  槽，自然不需求。
- 每节点车数固定写在内容里；车辆生产暂缓。修理类别与节点废墟
  暂缓——M3 可调的优先级类别只有建造与生产。

### 道路

- 全局 u8 图层 `frontline_td:logistics.road`（logistics 持有写者），
  `pave(cells, level)` 只升不降并推进道路版本。
- **道路只改线路的有效倍率，永远不改路由与连通**：拓扑搜索和
  连接距离判定始终用地形步进代价。这是对 0025「连线倾向沿
  道路走」一句的显式偏离，用户已批准——按线路升级（ADR 0029）
  之下路由随道路漂移会引入施工期拓扑振荡，收益不足以抵消
  复杂度。
- 有效倍率是**时间加权**（步进代价调和平均）而非 0025 字面的
  长度加权：`m = floor(cost·10000 / Σ step_k·10000/m(cell_k))`，
  步进代价记在目标格上，全程整数运算。仅在道路版本或拓扑变化
  时重算；每条线路存 `steps`（沿途各格步进代价）供复算。

### 走廊拦截

- 单位内容 `interceptor: { strength }` 经注入部件成为物流组件
  `Interceptor { strengthBp }`；raider（基础包）是首个拦截单位。
- 每个结算周期、每条线路：所有 InWorld 的敌对（按关系表）
  拦截者到折线任一格中心距离 ≤ `corridorWidth`（1.5 格，包围盒
  预筛）求和，系数 `max(0, 10000 − Σ)`。**这是对单条线路、单个
  方向的配额上限**——`cap = floor(配额 × factor / 10000)`，每笔
  分配再取 `min(剩余预算, cap − 本周期已载)`；不是逐分配乘系数
  （那样一串小需求会几何级绕过上限）。瓶颈归因仍指向该线路的
  付费节点，unmet 保持 `no_capacity`，线路在快照中记
  `intercept` bp。

### 拓扑增量失效与搜索

- 派生拓扑不序列化。节点集合变化只把本阵营标记为需重建；读档
  标记全部阵营。
- **阻挡增量失效**（本批性能修复）：`blockersChanged(cells,
  blocked)` 取代无条件重建。解除阻挡 ⇒ 全部阵营需重建（路径
  可能变短）。新增阻挡 ⇒ 只把敏感集命中的阵营标记为需重建，
  敏感集 = 全部线路折线格 ∪ 全部节点环格（`Uint8Array`，随
  重建生成）。**精确性论证**：阻挡只删边，任何距离都不会变短；
  折线与两端环都避开被阻格的线路，代价不变、最优环格不变
  （其余候选只会更远，按格下标的平局不变）、下降路径不变
  （已选前驱仍达到其距离，替代者只会更大）；不会有新线路出现；
  覆盖与挂靠是欧氏量，不受影响。性质测试在 proto_01 与小网格上，
  对每个 block/unblock 事件比较增量维护的拓扑与强制全重建。
- 同批优化：节点搜索共享 scratch 距离场（touched 复位）、扁平
  编码二叉堆、尽早退出回调，以及**按次重建的有向边步进代价
  缓存**（重叠的搜索不再重复算边）——结果逐位一致（黄金哈希
  与拓扑测试不变）。基线（`eval/baselines/perf-logistics.json`，
  210 节点 / 3000 消费者 / 600 tick）：`topoRebuildMs`
  2045 → 447 ms，`logistics.allocate` mean 4.21 → 1.15 ms。
  剩余成本：节点集合变化仍整阵营重建。

## 否决的方案

- 线性规划全局最优分配：每周期全量解 LP 对原型过重，付费方
  最短路 + 贪心已满足"运不过来要看得见"的目标。
- 逐分配乘拦截系数（曾实现）：小需求流可绕过上限，违反"拦截
  封顶线路"的语义。
- 道路改路由：见上，对 0025 的已批准偏离。

## 后果

- 客户端预览的配额估计（均匀步进权重调和平均）标注为估计，
  模拟权威。
- 增量失效把"任意一次占地/拆毁引发的拓扑重建"缩小到真正受
  影响的阵营；但任何命中敏感集的阻挡仍是整阵营重建，节点数量
  大时单次重建 ~0.5 s（210 节点量级）——后续可做线路局部修复，
  暂不做。
- 遗留：铁路（第二档）、节点集合的增量拓扑、废墟/修理、车辆
  生产、预览用排队量字段。
