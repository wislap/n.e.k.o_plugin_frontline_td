# 0046. 文档一致性约定

- 状态：已采纳
- 实现：已实现
- 日期：2026-11-20
- 决策者：wislap
- 批次：治理
- 领域：工程
- 部分取代：0001（ADR 领域取值"补给"改名为"物流"）

## 背景

一次外部文档审计逐条核对 ADR、设计文档与代码，发现三类系统性
偏差：ADR「实现」判定口径偏松（已采纳被当作已实现）；文档引用
依赖旧名字（领域"补给"早已改名"物流"）；功能 README 的「公开
接口」「对应设计」两节靠手写清单，必然随代码漂移。

## 决策

1. ADR「领域」字段的取值"补给"改名为"物流"，与 `gen-index`
   的 `ADR_DOMAINS` 一致；存量 ADR 头部已同步。
2. 「实现」判定按严格口径：决策条款中凡未被后续 ADR 取代且
   代码里找不到的部分，该 ADR 记「部分」并写清缺口。本次按此
   口径修正了 0004、0008、0012、0015、0023、0028、0031 的
   「实现」行。
3. 功能 README 的「公开接口」一节描述每个公开入口的用途与关键
   行为，并链接 `docs/generated/exports.md` / `contracts.md`，
   不手抄导出清单。
4. 「对应设计」一节的引用必须是 Markdown 链接，由 `check-docs`
   校验（后随批次落地检查）。

## 后果

- 文档与代码对不上的成本前置到写入时：「实现」判定不再有
  "采纳即实现"的模糊空间。
- 公开接口描述以语义为主、清单交给生成索引，减少一处会漂移的
  手工副本。
