# 0025. 物流模型：运力配额、统一货物与自动路由

- 状态：已采纳
- 日期：2026-11-15
- 决策者：wislap
- 批次：M1 前置
- 领域：物流

## 背景

补给是整个游戏的主轴（[game_design.md §4.5](../design/game_design.md)）：连通 + 运力、分配优先级、本地储备、节点血量、距离损耗、冗余线路、对称的敌方网络，并且要避免 HOI4 式的不透明。讨论中确定：物流的基本单位是运输车而不是人口；车站 / 补给站 / 主基地的定位由参数区分；连线长度按地面路径计算；所有货物走同一套系统，传输瞬时但受线路配额限制。目标体验：一次造几座塔基本无感，造多了开始排队，并明确显示是"运不过来"。

## 决策

### 术语
| 术语 | 含义 |
|---|---|
| 物流网 | 节点、连线、运输车与分配算法的整体；代码模块 `features/logistics/` |
| 运力 | 一条线路在一个结算周期内能运送的货物量（配额） |
| 货物 | 物流网运送的一切东西：资源（矿石、材料）与消耗品（能量、弹药）；每种货物是一个内容 ID |
| 补给 | 面向玩家的说法：消耗品（能量、弹药）送达消费者的情况；"补给状态"指消费者的存量是否充足 |

[ADR 0019](0019-factions-and-pluggable-modes.md) 等早期文档中的"补给网络"即本文的物流网。

### 统一货物、瞬时传输、配额限制
- 所有货物走同一套系统，没有专用通道。**生命线**（见优先级）就是专用通道的实现方式。
- **中央仓库**位于主基地，是 MVP 中唯一的仓库。所有流动要么从仓库出发（**出库**：建材、生产投料、能量、弹药），要么回到仓库（**入库**：矿机产出、工厂产品）。
- 每个**物流结算周期**（20 tick = 1 秒）结算一次：沿路径瞬时到账，同时占用沿途每条线路的配额。分不到配额的部分留到下个周期。
- 资源在被分配运输的那个周期才从仓库扣除；仓库存量不足与运力不足是两种不同的原因，分别显示。
- **建造、修复、升级的材料经物流网送达工地**（[ADR 0012](0012-construction-as-entity.md) 的"剩余物资"由工地的货物存储表示），进度受已送达材料的比例限制。

### 节点：一个组件，靠参数区分定位
- 车站、补给站、主基地是同一个 `LogisticsNode` 组件的不同参数：**连接距离**、**服务距离**、车辆数、各货物的储备容量。代码中没有"车站 / 补给站"分支（[ADR 0014](0014-data-driven-boundaries.md)）。
- 典型搭配：车站连接距离大、服务距离小、车多；补给站连接距离小、服务距离大、车少、储备多；主基地兼有两者并带中央仓库。
- 车站生产运输车（资源从仓库扣除，复用进度机制）。车是**计数**，不是地图上的实体；画面上的车队按实际流量生成，只是表现。

### 连接与拓扑
- 两个节点自动连接的条件：**地面路径长度 ≤ 两者连接距离中较小的一个**。范围内两两相连，物理拓扑完全由玩家放置节点决定（星形、网状都是放置的结果）。
- 连线长度 = 地面移动类别的寻路路径长度（道路格代价更低，连线因此倾向沿道路走）；连线的走廊是这条折线加宽度。只在节点建成、拆除、被占领，或地形、阻挡、道路变化时重算。
- 线路剪枝、玩家手动关闭线路以后再加。

### 运力配额
- 一辆车往返一条线路的时间 = 2 × 路径长度 ÷（车速 × 道路倍率）。由此线路单方向的配额：

  `配额 = 可用车数 × 每车载量 × 车速 × 道路倍率 × 周期 ÷ (2 × 路径长度)`

- **车按需调度**：每个节点每周期有"车辆时间"预算 = 有效车数 × 周期。货物经过一条线路时消耗两端节点的车辆时间（先消耗上游端，再消耗下游端），消耗量 = 2 × 运量 × 路径长度 ÷（载量 × 车速 × 道路倍率）。车不会闲在空线路上，多连一条线也不会稀释其他线路。
- **正反方向分开计**：每个节点出库、入库各有一份完整预算，题材上是送货的车回程捎带矿石。入库不挤占前线的出库。
- **末端配送**：节点到挂在它上面的消费者，同样消耗该节点的车辆时间（按土路倍率、直线距离计）。
- 整数运算，统一向下取整（[ADR 0020](0020-numeric-time-capacity-conventions.md)）。

### 路由与分配
- 路由全自动，每周期从头计算，不沿用上周期结果，因此不振荡、可复现。线路代价 = 路径长度 ÷ 道路倍率；每个需求走代价最低的、仍有余量的路径，线路饱和后自动改走次优路径（冗余线路的价值）。代价相同按节点 ID。实现上用从仓库出发的最短路树，有线路饱和时再重算。
- 需求的处理顺序：**优先级类别 → 请求开始 tick → 实体 ID**。请求开始 tick 对建造是下令时刻，对持续补充是存量上次补满之后首次下降的时刻。同一优先级内先到先得，不按比例平分（平分会让十座塔一起慢慢建、谁都建不完）。
- 优先级类别：
  1. **生命线**（固定最高，玩家不可调）：作战单位与防御建筑的能量、弹药补充。
  2. 玩家可调（默认顺序）：修复 > 建造 > 生产（工厂的能量与投料）。
  3. **储备补充**（固定最低）：节点本地储备。
  - 入库方向（矿机、工厂产品）单独排序，因为它只与入库竞争。
- 不用全局最优算法：贪心结果可以直接解释（"主路满了，改走 C，多花 X"），并且在固定顺序下天然确定。

### 货物存储与消耗
- 消耗品统一用**实体本地存储**表达：`CargoStore` 组件记录各货物的容量、存量与优先级类别。物流网的职责就是把存储补满。
  - 单位：电池（能量）与弹匣（弹药）。离开服务范围就无法补充，只能消耗自带的存量，**小队因此有续航半径**，推进太远会没电。
  - 防御建筑：少量能量与弹药存储，断线后还能顶一阵。
  - 工厂：能量存储，生产按周期消耗能量。
  - 工地：所需材料作为存储容量，送达即进度可推进。
  - 节点：各货物的本地储备。
- 消耗：
  - 基础维护（每秒）：单位、防御建筑的能量；数值是内容数据。
  - 活动消耗：武器每次开火的消耗（货物种类 + 数量）写在武器数据中（[ADR 0011](0011-projectile-effect-composition.md)），激光类耗能量，动能类耗弹药；单位移动可附加能量消耗。
  - 生产：配方附带能量消耗。
- **单一写者**：`CargoStore` 只由物流模块写入。其他模块读取存量判断能否行动（例如能否开火），并提交消耗意图，由物流模块在每 tick 的消耗阶段结算（[ADR 0008](0008-module-collaboration.md)）。运输补充每周期结算一次，消耗每 tick 结算。
- 节点储备的用法：消费者的需求先尝试从仓库经主干送达；送不到的部分（运力不足或断线）由所挂节点的储备补上，只消耗末端配送的车辆时间。储备因此同时缓冲断线和战斗时的消耗高峰。
- 补给状态按存量分档（满 / 不足 / 空），阈值是内容数据。效果通过修正值管线施加（[ADR 0013](0013-modifier-pipeline.md)）：能量不足先减速，耗尽则停机（机器人趴下）；弹药耗尽则动能武器哑火，仍可移动和撤退。

### 来源与生产
- 主基地自带基础能量产出，直接进入中央仓库，保证核心区域不断供（防止崩溃螺旋）。
- 发电厂、弹药厂是普通生产建筑：投料从仓库出库，产品先进入自身的小缓存，再入库回仓库。矿机同样把产出存进自身缓存，缓存满则停工并显示"运不回去"。生产建筑离仓库或主干越近，占用的运力越少，位置因此有意义。
- 多个仓库、产地直供消费者以后再考虑。

### 道路
- 默认所有线路都是土路（倍率 ×1）。道路是物流模块写入的网格图层（[ADR 0023](0023-grid-layers-groups-commands-rng-runtime-limits.md)）；线路的有效倍率按路径上各格的道路等级、以长度加权得出。道路属于地面而不属于某条线路，节点被毁后重建，道路仍在。
- 升级命令：`升级线路（线路列表，目标等级）`。每条线路的升级是一个建造实体（ADR 0012）：材料经物流网送达，从靠仓库的一端开始修，修好一段生效一段，可被攻击。
- MVP 只有一档升级（土路 → 道路，倍率由内容数据决定）；铁路作为第二档以后再加。

### 打击与损伤
- 拦截是一种能力：挂有拦截组件的敌对单位停留在线路走廊内时，该线路的配额按占据程度下降，直至为零（敌对关系按阵营关系表判断，[ADR 0019](0019-factions-and-pluggable-modes.md)）。哪些单位有这种能力是内容数据，设计上倾向只给少数突袭类怪物。
- 节点血量分档降低其有效车数；节点被摧毁时，其车辆与储备一并损失，留下废墟，重建比新建便宜。
- 与仓库不连通的部分只能靠各节点储备和实体自带存量运转，耗尽即断补给。
- 突袭怪破坏道路格、摧毁车辆以后再加。

### 可读性
- **物流视图**（地图信息层）：线路粗细与亮度表示流量，满载的线路发红，两者分开显示；覆盖范围显示在地面上。流量按最近约 30 秒的平均值显示，平滑只在客户端做，不影响模拟。
- **两下点击升级主干道**：第一下点击任意线路，UI 沿流量最大的方向向两端延伸选择，直到流量明显下降或到达主基地、末端节点，并预览造价、升级后的配额和这些线路上当前排队的运量；第二下确认。修饰键点击只选单条线路。延伸选择只是 UI 辅助，模拟只接收线路列表。
- 快照带每条线路两个方向的利用率，以及每个未满足需求的原因：**仓库缺货**（哪种货物）、**运力不足**（瓶颈线路）、**未接入**（不在任何服务范围内）、**断线**（与仓库不连通）。警告附带可执行的建议（加建车站、升级线路、增加产能）。
- 节点放置预览同时显示连接距离（会连上哪些节点）和服务距离。

### 架构落点
- 物流网是独立的图模块（[ADR 0009](0009-partial-ecs-boundary.md)）：节点是带组件的实体，拓扑由物流模块维护并增量更新；分配在节点图上进行。
- 契约组件：`LogisticsNode`、`CargoStore`。物流模块只服务挂了这些组件的实体，不知道塔、小队、工厂是什么。
- 每个阵营各有一张物流网与一个仓库，规则对称；某个阵营是否使用物流网由其规则原型决定（怪物可以换一套货物内容）。
- 物流覆盖是按阵营区分的网格图层；道路是另一层网格图层。
- 物流结算在评估框架中有单独的性能场景（[ADR 0024](0024-evaluation-framework.md)）。

### MVP 范围
货物：矿石、一种材料、能量、弹药。节点：主基地、车站、补给站。建筑：矿机、发电厂、弹药厂、一种动能炮塔。单位电池。自动连接与路由、按需调度、正反方向配额、优先级、节点储备、一档道路升级、物流视图与两下点击升级、走廊拦截。

### 否决的方案
- 运力即人口、维护持续占用运力：否决，物流的基本单位是运输车。
- 建造资源不经物流网瞬间扣除：否决，改为瞬时传输但占用配额，使"造多了运不过来"成为可见的限制。
- 专用通道独占配额：改为生命线固定最高优先级。
- 车站的车平均分配到各条线路：会稀释配额、浪费空闲线路的车，改为按需调度。
- 全网公共车池：瓶颈无法落到具体线路，改为按线路计配额。
- 按比例平分不足的运力：所有需求一起变慢，改为同优先级先到先得。
- 最优流算法：结果难以向玩家解释。
- 直线连线：改用地面路径，地形与隘口影响物流。
- 玩家逐格铺路：操作量大，且与自动连线冲突，改为一键升级已有线路。

## 后果

- 玩家需要做的决定只有：节点放在哪里、升级哪条主干道、（可选）调整优先级。其余都自动完成，复杂度集中在规划而不是操作上。
- 距离损耗、绕路、断线、储备消耗、主干道越用越集中，都是模型的自然结果，不需要特殊逻辑。
- 两个瓶颈手段各有取舍：加车站增加车辆，修路提高倍率。
- 小队的续航半径由电池自然产生，"推进"状态因此有了机制支撑。
- 连线长度依赖寻路，拓扑或道路变化时有一次重算开销；分配每周期从头计算，开销需要在评估框架中测量。
- 铁路、线路剪枝与手动关闭、手动指派车辆、突袭怪破坏道路或车辆、多仓库与产地直供、道路同时加速单位移动，留待以后。
