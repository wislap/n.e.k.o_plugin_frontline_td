# 0038. 据点、废墟、占领与禁建区

- 状态：已采纳
- 日期：2026-11-18
- 决策者：wislap
- 批次：M5
- 领域：模拟
- 部分取代：0035（波次目标）
- 部分取代：0019（归属变更方式：占领后新建实体，不改写 Faction）

## 背景

M5 批次 A/C 把「攻占据点」从设计文档落地：地图上有可被双方
反复夺取的前哨，据点周围产生建造禁区，据点与巢穴的残骸可
被占领拉锯，导演的怪物分队驻守并夺回据点。本文一次性记录
据点内容、废墟实体模型、占领规则、禁建区与导演的
驻军/夺还行为。

## 决策

### 据点内容（不是核心）

- 新结构 `frontline_td:outpost`：3×3 占地，hp 800，无 `build`
  块（不可建造、不可拆除），节点参数与补给站相同
  （connect 10 / service 10 / 车 3），储备能量 100、弹药 100，
  `exclusion` 12，`capture` { 半径 4，30 s 占领，20 s 重建 }。
  不含 `Core`——胜负条件不变，仍只看主基地 / hive。
- proto_01 三个点位均带开局驻军（南 3 爬 + 1 喷；西、东各
  4 爬 + 2 喷）：`outpost_south (30,55)` 在高地边缘与河之间的
  首个轻守目标；`outpost_west (26,21)` 贴着西矿场，禁建区罩住
  矿脉；`outpost_east (69,21)` 在东矿场侧。三点均为平地、
  不压坡/矿、在 hive 禁建区外、可从 `player_start` 地面到达，
  由内容测试断言。

### 废墟：construction 持有的无阵营实体

- 带 `capture` 档案的结构死亡（site 或 operational 同路）时
  `free_dead` 不解锁占地，而是生成废墟实体：
  `InWorld + Structure{kind,x,y} + Ruin 标签 + Position(占地中心)`
  + 注入的 `ruinParts`——**无 `Faction`**、无节点/储备/战斗/
  Core 部件；占地从死亡到重建全程封锁。
- 建筑表新增 `STATE_RUIN`（阵营列写 0，progressBp/hpBp 写 0）。
  取消/拆除/升级命令对废墟一律拒绝——无 owner 的实体本来
  就过不了归属校验，测试确认。

### 占领：拉锯规则与"换实体不改阵营"

- 新功能 `features/capture/`：`Capture` 组件经 `ruinParts` 注入，
  进度系统在 `capture_fog` 阶段逐 tick 运行。
- 半径内每个阵营的在场单位数 n 给速率
  `rate(n) = lnMilli(n·1000 + e·1000)`（n=0 为 0），取最高
  与次高：`net = A − B`。
  - 无单位：每 tick 衰减 `total/1000`（2%/s），归零后
    `owner = 0`；
  - `net > 0`：owner 为 0 或领先方 → 进度累加；owner 为落后
    方 → 进度削减，到 0 时 owner 翻转（不带余量结转）；
  - `net = 0`：停滞，`contested = 1`。
- 总进度 `total = ticks · lnMilli(1+e)`，恰好让 **1 个单位
  在 `seconds` 秒完成占领**。`lnMilli` 是 `core/int.ts` 的整数
  实现对数（2 的幂区间规约 + atanh 级数，不用 `Math.log`，
  满足纯度区约束），对硬编码表 n=1..200 及 1000/2000/1e6
  校验 ±1。
- 完成后发 `CaptureCompleted { ruin, faction, kind, x, y }`；
  construction 的重建系统（construction 阶段，下一 tick）校验
  废墟句柄仍存活，despawn 废墟并为占领方生成新工地，工期 =
  `rebuildTicks`。据点没有造价、不注入工地槽，进度是纯时间；
  重建工地照常可被打，再打烂回到废墟。
- 与 ADR 0019「只有占领模块改 Faction」的关系：实现选择
  **不改写 `Faction` 字段**，而是在同一占地上以新实体重生。
  语义等价（归属由新实体的 Faction 表达），且避免废墟→建筑
  的就地部件拆装；新建工地自然获得该阵营全部结构部件。
- 镜像测试确认 ADR 0019 对称性：阵营 1/2 互换、位置镜像时
  结果镜像。

### 禁建区

- 内容字段 `exclusion?: int`（格，1..64）：**运营中**的敌对
  结构以占地中心为圆心产生禁建区（outpost 12、hive 16）。
- `checkRange` 新增 `hostile_zone` 码，在覆盖/连通检查之前；
  蓝图在禁区内激活时保持 `waiting: 'hostile_zone'`，源头建筑
  倒下后自动开工。废墟（无阵营、非运营）不产生禁区。
- 客户端 `makePlacementView` 用同一规则实现 `excluded`，
  并合并视野记忆表里记住的敌对建筑（记忆行按定义不可见，
  不会与建筑表重复）；敌意判定经 `MatchSetup.relations` 换到
  客户端（`client/hostility.ts`），替换「非我非中立即敌」的
  默认近似。

### 导演驻军与夺还（取代 ADR 0035 的波次目标段）

- 驻军小队 tag `garrison:<x>,<y>`，x,y 为据点占地左上角，
  跨重建稳定。导演初始化时，每个己方运营据点 8 格内的怪物
  编成该据点驻军（strength 6，驻守令在据点中心、半径 6）；
  其余非掠袭怪物进 `hive_guard`——其驻守点改为建筑表里
  己方 hive 的中心，不再是全体怪物质心（修正了驻军被
  hive_guard 吸走、离开据点的缺陷）。
- 每次决策：缺驻军小队的己方运营据点用未编队的非掠袭怪物
  重建一支（strength 6、同驻守令）；补员只靠通用小队增援
  规则（最大缺口优先）。据点失守后驻军小队不撤不散——
  留在原地的守卫会继续以存在参与废墟拉锯/夺还。
- 集结时的波次目标：先在占领废墟与敌对据点（运营或工地
  均可）中取离集结点最近者，没有再退回 ADR 0035 的「最近
  敌对建筑」。**本段取代 ADR 0035 中「目标 = 最近敌对建筑」
  的描述**（0035 不修改）。
- 全部状态从小队 tag 推导，`save()`/`load()` 无新增字段。

rush 局（约 20 分钟）；balanced 反而在第 2 波失守最快。
数值仍按 M4 决定不调。
