# 0065. Supply Line v1.5：生命线分段分配、可交付挂载与缺能惩罚

- 状态：待定
- 实现：未实现（缺：生命线分段分配、可交付候选挂载、供给状态契约与缺能行为均未落地）
- 日期：2026-11-29
- 决策者：wislap
- 批次：补给线规则提案
- 领域：物流

## 背景

现有物流模型（[ADR 0025](0025-logistics-model.md)）的“节点—连线—车辆时间预算—本地货槽—走廊拦截”已能表达补给线，但五个体验缺口仍未收口：

1. 生命线与建造共用“最早请求 + 补到满”的先到先得。运力长期不足时，先排序单位先满电，后排序单位可能持续停摆。
2. 普通消费者静态挂到覆盖范围内欧氏距离最近的节点；最近节点与仓库断开、次近节点仍连通时，请求会被判为断线。
3. `outSat/inSat` 只能表达“付费节点预算接近耗尽且有流量”，无法说明是配额、末端、拦截还是仓库缺货限制了交付。
4. 能量档位修正目前只进入 `MoveSpeed`；基础炮塔有能量维护消耗，但空电不禁止开火。
5. 空电机器人速度修正为 −10000，在覆盖区外耗尽后无法自行返回；小队平均电量回撤会掩盖个别濒空成员。

本 ADR 是待负责人拍板的规则提案，不包含实现。现仓库代码按 `main` 提交 `1fab51c` 核对；若采纳，将以本 ADR 的决策替换上述行为，并以新 ADR 的元数据标注对 0025、0031、0034 的部分取代关系。

## 决策

### 范围

- 保留瞬时结算、固定 tick、整数数量、稳定遍历与确定性；不引入真实车辆实体、逐车寻路、多仓库、手动路线、真实飞行时间或敌方对称物流网。
- 不改运力核心公式：线路成本 = 地面路径成本 / 道路有效倍率；节点预算 = 有效车辆数 × 每周期车辆时间；单次交付仍受仓库库存、沿途付费预算、拦截后配额与末端预算共同限制。
- 补给线仍分三层：空间层回答“理论上能否到达”，运输层回答“本周期能送多少、卡在哪里”，消费层回答“拿到多少、还能维持什么行为”。

### 生命线：紧急保底 + 限量批次

- 生命线仍固定最高优先级；建造、生产保持现有类别顺序与先到先得；节点储备仍固定最低；入库继续使用独立预算。
- 第一段只处理生命线货槽低于危急线的部分，先补到容量的 30%。顺序为当前存量比例升序 → 请求开始 tick → 实体 ID → 槽位；存量为 0 的槽最先处理。主路径不足时允许节点储备兜底。
- 第一段全部完成后，才允许生命线继续补向高位。
- 第二段按轮次分配：每个实体每轮最多获得容量的 25%。顺序为上次成功获配 tick → 请求开始 tick → 实体 ID → 槽位；从未获配者排最前。成功获配后更新 `lastServedTick`，一轮结束后仍有余量再进入下一轮。
- `lastServedTick` 必须进入序列化状态并在实体生成时初始化，不能留下跨局状态。
- 这不是按比例平分；只是给单次取货设批量上限，避免一个大货槽独占整轮。
- 不在紧急段或批次中间写最终警告；全部生命线轮次结束后统一计算未满足原因，避免中间态误报。

### 覆盖与挂载分离

- 服务覆盖继续表示节点周围可提供末端配送的空间集合，用于显示、建造预览和小队寻找回充区域。
- 供货挂载表示某货槽本周期实际由哪个节点送货，不再等同于覆盖数组里的最近节点。
- 为覆盖格保留候选节点列表，按末端距离 → 节点实体 ID 稳定排序。分配时依次检查：当前出库预算树能否到达该节点；或该节点是否有对应货物储备且末端预算足够。第一个可满足本次分配的节点成为本周期供货节点。
- 所有候选都无法供货时，仍按最近节点和最优可行路径生成失败原因；所有候选都无货时报告仓库缺货，而不是未覆盖。
- 不为“防抖动”永久粘住上一周期节点；每周期重算，保持无粘滞、可解释。若实测频繁换源，再评估可序列化粘滞。
- `FixedAttach`、工地节点接入最佳既有节点、节点自挂载的规则不变。

### 状态与归因

- 不使用单一补给状态枚举。消费者至少拆成连接状态、交付来源、存量状态三个独立维度，并附带未满足原因、容量限制类型与瓶颈节点。
- 交付来源区分 `warehouse` 与 `node_reserve`；靠节点储备维持时 UI 明确显示“节点储备供给”，不能继续显示仓库直供。
- `UNMET_NO_CAPACITY` 保持不变，其下增加限制类型：付费节点预算、末端配送、走廊拦截、线路配额。多个限制同时存在时展示本次实际取到的最小限制；完全并列按写入 ADR 的固定优先级取主原因，其余作附加信息，不依赖对象遍历顺序。
- 线路快照分别记录配额、实际交付、未满足量、利用率、拦截强度、限制类型与瓶颈节点；客户端只对最近 10–30 秒做显示平滑，平滑结果不回写模拟。
- “需求估算”和“实际交付”分开命名；没有准确逐线未满足量时只在瓶颈路径归因，不为填满接口编造数值。
- 警告按“瓶颈节点 + 货物 + 原因”聚合，点击跳到瓶颈并给出对应动作：未覆盖建站或撤回，断线查断口，缺货查产能，运力不足升级道路或加车站，被拦截定位走廊并派兵清理。

### 缺能行为与小队回撤

- 需要供电的武器必须有数据字段 `powerRequired`；不得按内容 ID、实体名称或“炮塔”种类写特判。无电池怪物武器不受该规则影响。
- 低能量（低于容量 30%）时，机器人移动速度降至 25%，供电武器冷却 ×2；空能量时机器人保留 10% 应急移动，供电武器禁止开火。弹药耗尽只禁止动能武器开火，不直接妨碍移动和撤退。
- 空电不再使用固定 −10000 永久停机；保留最低自恢复路径，避免覆盖区外耗尽即永久报废。若坚持完全停机，必须同时提供救援、拖回或空投机制，本期不做救援系统。
- 小队进入 `resupplying` 的条件扩展为任一成员电量 ≤10%，或低电成员占比 ≥1/3，或平均电量 <30%；退出条件为所有带电池成员电量 ≥80% 且已处于可交付覆盖区。无电池成员继续排除。比例是初始调参建议，不作为代码正确性断言。
- 战斗冷却若接入修正值管线，按 [ADR 0031](0031-combat-modifiers-inspect.md) 通过 `ctx.stat` 读取，不另写随机惩罚。

### 模块与接口边界

- 继续放在 `frontend/src/features/logistics/`，不新建 supply 模块；补给只是物流面向消费者的语义。
- 运输执行器只关心“本轮最多送多少”和候选节点，不知道机器人、炮塔、工厂等具体类型。
- 分配先完成全部校验，再统一扣仓库、扣预算、加货槽；候选节点尝试失败不能留下半次修改。
- 模拟状态仍由物流模块单一写入；客户端只消费 `protocol.ts` 与只读快照，不 import `sim/`、`kernel/` 或 `runtime/`。
- 新增协议字段、检视器分节与线路指标后，重新生成 `docs/generated/`，并检查公共接口 diff。
- 分阶段实施，每阶段独立评审与验收；首批只做生命线分段、可交付候选挂载、交付来源/主原因/瓶颈显示、空电应急移动与供电武器停火。

### 初始参数

- 危急线 30%、每轮批次 25%、低电阈值 30%、低电速度 25%、空电应急速度 10%、低电冷却 ×2 仅为首轮试玩起点，不是平衡结论。
- 参数集中命名，测试不断言具体平衡值；平衡数据放 `frontend/eval/` 评估。

## 后果

- 运力不足时先避免“有人完全停摆”，再逐步补满；建造与生产不被生命线批次逻辑改变。
- 覆盖重叠且最近节点不可用时，货物能从真正可交付的节点送达；同名同距离候选按节点 ID 确定，结果可复现。
- 玩家能区分未覆盖、断线、缺货、运力不足、被拦截与本地存量偏低；瓶颈可定位到节点或走廊。
- 空电不再等于永久报废，但 10% 速度加停火仍让冒进昂贵；弹药与能量的后果保持独立。
- 代价是候选节点枚举、协议字段与检视器 UI 增多；候选列表在拓扑重建时生成、周期内复用，先测量再优化。
- 生命线分批可能让总吞吐看似变慢，但只在运力不足时改变顺序，总量公式不变，需用对局评估验证。
- 若采纳，需要更新 [ADR 0025](0025-logistics-model.md)、[ADR 0031](0031-combat-modifiers-inspect.md)、[ADR 0034](0034-squads.md) 的部分规则，并在本 ADR 头部补记部分取代关系；不修改旧 ADR 正文。
