# 0041. 门禁与索引 v2

- 状态：已采纳
- 日期：2026-11-18
- 决策者：wislap
- 批次：治理
- 领域：工程
- 部分取代：0017（棘轮的超长文件阈值、公共接口清单的形式）
- 部分取代：0001（ADR 头部字段：新增可选的"部分取代"行）

## 背景

M5 完成后做一次治理收口：0017 的 400 行棘轮在 M5 期间已经三次迫使功能完整的文件为了过线而拆分（拆分的边界是行数而非职责）；ADR 0038 只需要取代 0035 的波次目标一段，整篇取代过重、不改又没处表达；ADR 0040 立了"读组件数组前先查 has"的规矩，但缺一个能持续暴露违例的机制；kernel 一直没有一个自描述接口，契约清单只能手写；浏览器端没有任何自动验收。

## 决策

1. **文件行数双阈值**：>800 行计入棘轮指标 `longFiles`（基线 0，变差即失败）；(600, 800] 只打印警告列表，不失败、不进基线。豁免范围（两个阈值都不计入）：`*.test.ts(x)`、任何 `test-world.ts`、`src/kernel/testing/` 下全部文件——测试与测试基建天然按场景堆叠，按职责拆分的收益低于长文件的可读性损失。原 400 行红线废止。
2. **ADR 部分取代**：新增可选头部行 `- 部分取代：NNNN（说明）`，一个目标一行、可写多行。gen-index 校验目标存在且编号更旧（编号字典序即时间序），并在被引用 ADR 的索引行派生"部分被 MMMM 取代（说明）"。旧 ADR 正文永不编辑；取代关系只写在新 ADR 头部、展示由索引生成。
3. **DEV-only 陈旧数据投毒**（落实 [ADR 0040](0040-entity-id-reuse-component-reads.md)）：`import.meta.env.DEV` 下，组件移除与实体销毁时把该 id 的字段写成毒值（整型写类型最大值，浮点与 handle 写 NaN）；生产构建不含投毒，存活性数据与存档 / 哈希不变。同时修复了它暴露的真实缺陷：spawn 附加组件此前不清零未指定字段（与 `add` 路径的 `clearFields` 不变量不一致），以及建造快照通道对无 `Faction` 的废墟读取了回收槽位的两处读法。首批共暴露并修复 3 处陈旧读。
4. **`Simulation.describe()`**：kernel 只读自省 API，返回纯数据的 `SimManifest`（阶段、逐模块的系统/命令/效果/通道/状态/检查器/探针、组件写者、网格层写者、消息种类与可见性），顺序确定（阶段序、注册序、id 序）。属 kernel 改动，按本文记录。
5. **生成索引扩容**：`docs/generated/contracts.md`（真实攻占模拟的清单渲染，经共享的 Vite SSR 装载器跑 src 公共桶）与 `docs/generated/exports.md`（TypeScript 编译器 API 枚举各公共桶的导出名、声明种类与文档注释首句）。输出按字节稳定（LF、排序），`check:index` 检查新鲜度。
6. **整局黄金 + 行为冒烟**（`eval/match-smoke.test.ts`）：proto_01 上平衡机器人 vs 导演 5 分钟（6000 tick）。断言：终局哈希等于黄金常量；`assault.waves.f2` ≥ 1；逐秒采样无小队连续 `resupplying` 超 120 秒；全部单位位置有限且在图内。约 12.6 秒。规则变化允许改哈希：常量在同一次提交里更新并在提交信息里写明原因。
7. **Playwright 浏览器冒烟**：`@playwright/test` 1.65.0（2026-11-05 发布，是当时满 7 天的最新稳定版；1.65.1 发布不足 7 天）。Chromium only；`vite preview` 服务真实 `static/` 产物（不开 dev server）。断言：应用挂载、`data-sim-tick` 推进（worker 在跑）、画布非纯色、空格暂停后 tick 停走；NEKO SDK 脚本 404 是唯一容忍失败，其余任何 `pageerror` / `console.error` / 失败请求都判负。`npm run e2e` 是 `frontend.yml` 中 verify 之后的独立步骤，不进 `npm run verify`。
8. **PR 模板**：性能热点（模拟系统、物流、寻路、渲染循环）改动须勾选已跑 `npm run eval:perf` 并对比 `eval/baselines/`。

## 后果

- 超长文件只对真正的臃肿报警，测试豁免后 `test-world.ts` 模式不再受行数驱赶；警告带(600, 800]让人提前看见风险但不阻塞。
- 部分取代有了可机读的表达，索引自动派生反向标注，旧 ADR 不动。
- 投毒把"回收 id 的脏读"从潜伏缺陷变成测试期即炸的错误；任何新增失败都指向真实漏读，禁止削弱投毒迁就。
- 契约文档随代码自动保鲜，PR 里系统/组件/消息变化直接显形。
- 仍未覆盖的防线（后续再补）：`OPERATIONAL_EXCLUDE` 仍靠各系统自觉（无强制）；控制器 `save`/`load` 的完整性目前只有机器人测试兜底；React 组件测试仍缺（见 [architecture.md §13](../design/architecture.md)）。
