# 0022. 对局启动参数、内容 ID 与内容包

- 状态：已采纳
- 实现：部分（缺：别名表与包补丁未做；组件序列化 u16 内容索引，存档与内容版本绑定）
- 日期：2026-11-15
- 决策者：wislap
- 批次：M1 前置
- 领域：内容

## 背景

存档和回放引用内容 ID，改名或删除内容会让旧存档失效。以后可能支持 mod，或者让内容组织得像 mod：仅按类别加前缀的 ID（如 `building.laser`）无法避免两个 mod 互相冲突。回放、存档、无头测试、将来的 PVP 都需要一份统一的开局描述（[ADR 0015](0015-map-format-versioning.md)、[ADR 0019](0019-factions-and-pluggable-modes.md)）。

## 决策

### 内容包
- 所有内容都属于某个**内容包**。本体内容也是一个包，包 ID 为 `frontline_td`（与插件 ID 相同，因此和市场 ID 处于同一个唯一性空间），与将来的 mod 走同一条加载管线：同样的 schema 校验、同样的加载与索引分配，本体没有特权路径。
- 包 ID 的唯一性：
  - 经 NEKO 插件市场分发的包，包 ID 就是市场 ID（`^[a-z][a-z0-9_]*$`，市场保证唯一）。
  - 本地包使用 `<GitHub ID>.<名字>`：GitHub ID 转小写、`-` 换成 `_`（GitHub ID 不含 `_`，换算不会撞），名字为 `[a-z][a-z0-9_]*`。带点的形式与市场 ID 不会相撞。
  - 加载时两个包 ID 相同，拒绝加载并明确报错，不允许后加载的覆盖先加载的。

### 内容 ID
- 形式为 `包ID:名字`，例如 `frontline_td:turret_basic`、`acme:laser`。名字为 `[a-z][a-z0-9_]*`。
- 类别不写进 ID，由所属注册表决定（建筑表、怪物表、武器表各自独立）；类型上用不同的 branded 类型（`BuildingId`、`MonsterId` 等）区分，误传在编译期报错。
- **ID 一经发布不再修改**；确需改名时，通过内容迁移中的别名表映射旧 ID。
- 模拟内部使用加载时分配的数字索引：按完整 ID 排序后分配，保证确定性。存档与回放只存字符串 ID，**数字索引永远不写入存档**。

### 同一命名规则适用于所有注册表键
具名行为、调度器效果类型（[ADR 0021](0021-scheduled-effects-entity-relations.md)）、命令与事件类型、RNG 流名、地图 ID、资源路径、内容文本的 i18n 键都按 `包ID:名字` 命名。内容文本使用以包 ID 为名的 i18next 命名空间。

### 修改其他包的内容
- 必须写成显式补丁：声明目标 ID 与要修改的字段；不允许重新定义已存在的 ID。
- 补丁按确定的加载顺序应用；两个补丁修改同一字段时报告冲突，不在暗中决出胜负。

### 对局启动参数（MatchSetup）
- 一份可序列化、带 `formatVersion` 的数据：启用的内容包列表（各自的版本与内容哈希）、地图 ID、种子、玩法 ID、参与阵营列表（各自的规则原型、控制者类型、开局状态、局外带入的配置）。
- 回放 = MatchSetup + 命令日志 + 构建 ID；存档 = MatchSetup + 状态快照。回放与 PVP 要求双方启用的包完全一致。
- 玩法 ID 只由 `app/` 用来选择装配哪个玩法，模拟系统读不到它（ADR 0019）。
- 存档引用的包缺失时，拒绝加载并列出缺少的包。

### 暂不做
- **带代码的 mod**（mod 自己定义新行为）：第三方代码在运行时无法强制纯度与确定性，还涉及安全沙箱，做的时候另写 ADR。现在只保证纯数据 mod 不被架构阻碍。
- mod 的发现、安装与启用界面。

## 后果

- 加内容、加包都不会与已有 ID 冲突；本体通过 mod 管线加载，mod 支持天然被测试。
- 所有注册表键都比单纯的名字长一些，换来的是统一的冲突规则。
- 内容迁移（别名表）成为内容体系的一部分，随 `formatVersion` 演进。
