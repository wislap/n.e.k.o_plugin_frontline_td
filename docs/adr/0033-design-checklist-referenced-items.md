- 状态：已采纳
- 日期：2026-11-17
- 决策者：wislap
- 批次：M3 跨模块参考实现
- 领域：工程

## 背景

团队的《设计决策清单 v2》（2026-11-15，c酱整理自与云玩家的
私聊）是**非规范性的团队输入**——清单自己声明"不是替任何人
做决定"；本仓库的 ADR 才是权威。但清单在仓库外（PDF），ADR、
architecture 引用了其中若干条目编号，读者无法查证。本文档把
**被引用的条目**如实转写，并说明本项目如何采纳或偏离。

## 决策

### 被引用条目转写

- **A1 游戏模式结构（已定）**：MVP 只做能承载各种玩法的底座，
  不在感染/公司竞争之间二选一。底座（默认玩法「攻坚征服」）：
  大地图、敌方已发育完成、玩家发育并攻占敌方据点、最终攻克
  敌方基地；对称与感染模式在底座上扩展。→ 本项目按"玩法可
  插拔"实现（ADR 0019）：通用模块不感知玩法，M4 装配
  `modes/assault/`。
- **A2 我方成长系统（已定·部分）**：科技系统取代已撤回的
  时代框架；攻下一张地图得科技点解锁更先进内容，跨关累积；
  局内成长暂不定。→ M5 做局外科技占位（architecture §1.2）。
- **A6 MVP 范围（已定）**：①网格地图 + 矿机 + 一种生产建筑 +
  建造需物资送达 ②补给网一层 ③小队两种状态（驻守、推进）
  ④一个敌方集结点 + 一次反攻 + 路线箭头 ⑤单摄像机 3D 观战 /
  正交指挥切换 ⑥无界面对拍工具 + 四个策略机器人 + 状态哈希
  测试。不进 MVP：传送带、多品类边、Yui 指令、局外星球、藏品、
  多人、mod 接口、WebGPU 等。→ 里程碑表（architecture §1.2）
  逐条对应：①②③在 M3/M4，④⑤在 M4/M2 已部分落地（镜头见
  ADR 0028），⑥是 M4 验收。另加一种基础炮塔（已落地）。
- **A7 发行与商业模式（已定）**：只发 GitHub Release 与 N.E.K.O
  插件市场；一定开源，许可证（是否自由软件）未定；收入靠赞助
  不强制收费。→ 仓库现持 MIT，copyleft 与否留 §13 待定行
  （ADR 0018）。
- **D4 主动拆除返还 100% 造价、消耗工时（大体认可；「升代废弃
  按残值返还」半句作废）**。→ 部分采纳（[ADR 0029](0029-construction-implementation.md)）：
  拆除耗时 `demolishTime` ✓；但返还款按内容参数 `salvageBp`
  折算，当前值 5000 = **50% 造价**——与"返还 100%"的偏离
  留在内容数值里，未完工工地的取消退款则是已交付量的 100%。
- **D6 + D12 + D14 维护与人头（大体认可；保险丝数值需按 D16
  重新定）**：维护 = 持续占用补给运力；不设人口上限，只留
  性能保险丝；一次性扣费不算维护（D6+D12+D14 合并为「运力即
  人口」）。→ 有偏离：本项目**既没有人口上限，也不设性能
  保险丝**（ADR 0024、AGENTS.md——性能问题从根源解决，不用
  上限掩盖）；"维护 = 持续占用运力"采纳为存储槽的持续消耗
  （单位电池、炮塔能量的 `ratePerSecond` 负率，每周期入账）
  经物流网补充，而不是抽象的"人头"。
- **D10 随机只在选项里，效果确定（大体认可）**。→ 与 ADR 0006
  确定性规范一致：模拟内只有带种子 RNG 流，效果一旦选定即
  确定。
- **D16 军队规模（已改）**：全局单位会超过 1000，玩家指挥小队
  和更大的编组，而不是 8–16 个单体。→ 规模假设写进
  architecture §3.2/§13；性能场景按千级设计（ADR 0024 的
  `eval/`）。
- **D17 补给拦截（大体认可）**：补给拦截 = 敌方单位进入补给
  线路的走廊；车队只做表现。→ 采纳（[ADR 0030](0030-logistics-implementation.md)
  的走廊拦截）：敌对拦截单位在走廊内按强度削减线路配额；
  表现层目前不渲染车辆，被拦截线路在物流视图标记。
- **D21 插件分包（大体认可，按市场规则执行）**：本体 ≤ 32MiB
  （解压后 ≤ 128MiB）；3D 素材运行时下载需写明并有校验；**代码
  和可执行文件不能运行时下载**。→ ADR 0023 落定后者为 lint
  规则；`check-size` 把 static 体积锁在阈值内（当前 1.36 MiB）。

### 缺失原文的条目

清单自述 D2、D5、D7 原文缺失。本仓库没有引用它们；如其决策
内容将来需要，按清单说法"需要谁有出处补一下"，不在本文档
杜撰。

## 否决的方案

- 全文转写清单：清单大部分条目与本仓库无关（感染模式细节、
  美术、宣传口径），无引用价值；只转写被引用条目并把清单原文
  的"状态"一并保留。
- 把清单当需求源写进正文：清单是非正式输入，正文一律引 ADR。

## 后果

- docs 中"设计清单 X##"引用指向本文档条目而非外部 PDF。
- 清单更新（v3）出现时按引用条目增量修订本文档。
