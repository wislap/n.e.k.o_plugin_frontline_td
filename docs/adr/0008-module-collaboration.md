# 0008. 模块协作模式

- 状态：已采纳
- 实现：已实现
- 日期：2026-11-14
- 决策者：wislap
- 批次：M0 架构基线
- 领域：架构

## 背景

多个模块需要读写同一份模拟状态，必须防止隐式耦合与写冲突（[architecture.md §7.2](../design/architecture.md)）。

## 决策

模块协作六条规则（[§7.2](../design/architecture.md)）：

1. **契约组件**：放在 kernel，数量少、稳定。组件默认归属某个模块，两个以上模块确实需要时才升级为契约组件。
2. **单一写者**：每个组件只有所属模块能写；组件存储不导出，外部只拿 `readonly` 视图（类型层面强制）。其他模块要改，就提交意图，由所属模块在结算阶段统一处理。
3. **意图 → 结算**：争用状态（血量、资源、格子占用、补给分配）由各系统提交意图，所属模块在固定阶段统一结算。伤害结算是固定顺序管线：基础值 → 修正值 → 抗性 → 护盾 → 血量；新机制以声明方式插入阶段。
4. **事件只通知"已经发生"**：需要答案时调用对方公开查询函数。事件在阶段边界统一处理，处理中产生的新事件进入下一阶段；不递归、不在同一阶段内连锁。
5. **窄查询接口**：跨模块读取经由公开函数，不读对方内部数据。
6. **跨 tick 只保存句柄**（ID + 代数），使用前经 kernel 校验有效性；禁止跨 tick 保存原始实体 ID。

执行阶段顺序显式声明，部分系统按 tick 取模降频（[§6.5](../design/architecture.md)）。

## 后果

- 事件让调用链隐式：生成"哪个模块发出 / 消费哪些事件"的索引（[§8](../design/architecture.md)）。
- 系统执行顺序是全局耦合，调整顺序视为架构级改动。
