# 0044. ADR 实现状态字段

- 状态：已采纳
- 实现：已实现
- 日期：2026-11-18
- 决策者：wislap
- 批次：治理
- 领域：工程
- 部分取代：0001（ADR 头部字段：新增必填"实现"行，与"状态""部分取代"同属可更新的元数据）

## 背景

`已采纳`只说明决策成立，不说明代码已经做到。实践中 agent 与人都容易
把"有 ADR"当作"已实现"，两次评审都踩中了这一点：审计逐条核对
0001–0043 的决策与代码，发现 6 篇存在已采纳但未落地或部分落地的
条款（如 0022 的"存档不写数字索引"与 0010 的分区失效）。正文不可改
的原则不变，但实现进度是随代码演进的事实，必须有一处权威位置记录。

## 决策

每篇 ADR 在 `- 状态：` 行后新增一行必填头部字段，语法由
`gen-index.ts` 校验：

- `- 实现：已实现` — 决策已落地；可附 `（注：…）` 说明使用范围
  （如"目前仅 MoveSpeed 使用"）。
- `- 实现：部分（缺：…）` / `- 实现：未实现（缺：…）` — 必须写一条
  具体缺口，`缺：` 后不能为空。
- 判定针对该 ADR 的"决策"一节，不含"待定"事项；被后续 ADR 部分取代
  的条款按未取代部分判定。

该字段与"状态""部分取代"一样属于可更新的头部元数据：落地缺口时更新
对应 ADR 的"实现"行即可，正文仍不改动。维护方式：PR 模板新增一条
检查项；里程碑/评审时对照审计口径复核一遍"部分""未实现"清单。

`adr-index.md` 增加"实现"列，索引即审计视图。

初始审计（0001–0043）结论：已实现 37、部分 6、未实现 0。六条缺口：

- 0010：分区失效仍是全局（invalidateCells 清全图 fields/portalDists，
  rebuildNodesAndEdges 全局重编号）。
- 0011：仅 instant 交付；追踪、抛物线与区域效果包未做。
- 0014：局内解锁未做，carryIn.unlocks 有 schema 无消费方。
- 0022：别名表与包补丁未做；组件序列化 u16 内容索引，存档与内容版本
  绑定。
- 0023：嵌套编组未做（小队单层）；经济收入来源注册接口未做。
- 0025：修复优先级类别与节点修复未做；被毁节点不留废墟、无重建折扣（据点废墟是 ADR 0038 的另一机制）。

0022 的"存档不写数字索引"保持为目标：现状是组件字段存 u16 内容索引
且存档随内容版本绑定，待跨版本存档需求出现时再设计索引↔ID 翻译层，
届时新写 ADR 或更新本字段。

## 后果

- 新 ADR 自本篇起必须带"实现"行，gen-index --check 强制。
- 读 ADR 时先看"实现"再引用决策，避免把愿景当现状。
- "部分""未实现"清单成为路线图素材，缺口落地即更新行值。
