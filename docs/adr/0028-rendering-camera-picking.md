# 0028. 渲染、镜头与拾取

- 状态：已采纳
- 实现：已实现
- 日期：2026-11-16
- 决策者：wislap
- 批次：M2 第一个参考实现
- 领域：UI

## 背景

[ADR 0003](0003-tech-stack.md) 选了 Three.js + React Three Fiber，architecture 要求 3D 观战视角和 2D 正交指挥视角是**同一个场景、只切镜头**。M2 第一次把渲染接上快照，有几条约定会被之后所有渲染和交互代码沿用：坐标怎么对应、逐帧数据从哪里读、两种镜头怎么切、鼠标点到的是哪一格。

## 决策

### 依赖与边界
- 引入 `three@0.187.0`、`@react-three/fiber@9.8.2`、`@types/three@0.187.0`（开发依赖），精确版本。不引入 drei 等辅助库，需要的小功能自己写。
- three 和 R3F 只能出现在 `src/render/`、`src/features/*/render/` 和 `src/app/`，由依赖规则 `three-only-in-render` 强制。

### 坐标
- 地图格 (x, y) 对应场景 X = x、Z = y，Y = 高度层级 × 0.5。地图北（y = 0）在两种镜头下都朝屏幕上方。
- 只有 `render/world.ts` 做这层换算，其他代码不写死。

### 逐帧数据
- 地形网格在第一份快照到达时一次性生成（M2 地形是静态的）：一个合并的几何体，顶点着色，悬崖面加深，坡道是斜面，叠加很淡的棋盘格便于在指挥视角数格子。地表颜色来自内容数据。
- 单位用 InstancedMesh 绘制，容量按翻倍增长。在 `useFrame` 里直接读客户端保存的上一份和最新一份快照，按句柄配对做插值。逐 tick 的实体状态不进 React state 或 zustand（AGENTS.md）。
- 镜头模式、选中的单位属于 UI 状态，放在 zustand。

### 两种镜头
- 观战：透视镜头，视场 45°，俯角 55°。指挥：正交镜头，垂直向下。两台镜头的 up 方向都是地图北（场景 −Z），俯角到 90° 时也不会退化。
- 按 V 切换，400 ms 过渡，保持画面中心不动：从观战切到指挥时，透视镜头先把俯角抬到 90°，并同时调整距离，让看到的地面高度和目标正交视野一致，然后换成正交镜头；反向同理。两种镜头在交换的那一帧看到的地面范围相同，画面不跳。这条匹配关系是纯函数，有测试。
- 每次切换模式（包括自动切换）都换算缩放值，保持看到的地面范围不变。
- 暂停时默认自动切到指挥视角（可在设置中关闭），恢复时只在之前是自动切换的情况下切回观战。M3 的建造模式沿用这条机制。

### 输入与拾取
- 连续输入（WASD 平移）是"按住的键集合"这种状态，由镜头每帧读取；离散操作（切镜头、框选、移动命令）走"输入 → 意图"。
- 地面拾取：从屏幕点发出射线，以 0.25 格步长沿高度场步进，碰到地面后二分 6 次。指挥视角下结果精确，观战视角下考虑了高度。纯函数，测试覆盖平地、高地边缘和坡道。
- 点选取离点击处 0.6 格内最近的己方单位；框选取屏幕投影落在框内的己方单位；快照里消失的单位自动移出选中集合。右键对选中单位下达 `movement.move` 命令。

## 后果

- 两种视角共用一套场景和数据，之后新增的渲染层（建筑、物流线、迷雾）只写一次。
- 不用 drei 意味着镜头和拾取要自己维护，但代码量小、行为完全可测。
- 浏览器端的端到端测试推迟（architecture §10），交互靠纯函数测试和人工检查。
