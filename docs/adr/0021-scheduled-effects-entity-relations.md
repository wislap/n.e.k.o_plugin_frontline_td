# 0021. 延迟效果与实体关系

- 状态：已采纳
- 日期：2026-11-15
- 决策者：wislap
- 批次：M1 前置
- 领域：模拟

## 背景

延迟必中的弹道、持续伤害、"3 秒后爆炸"都需要确定性的延迟执行；各模块自写计时器会破坏确定性与可序列化。小队成员、驻防（小队进入地堡）、挂在建筑上的武器都是实体之间的关系，需要统一的建模方式（[game_design.md §4.7、§4.8](../design/game_design.md)）。

## 决策

### 延迟效果：kernel 调度队列
- kernel 提供调度队列，条目按（到期 tick、阶段、插入序号）排序；插入序号单调递增，同一 tick 同一阶段到期的条目顺序确定。
- 条目只存数据：效果类型 ID（按 [ADR 0022](0022-match-setup-content-ids-packs.md) 命名）、可序列化的参数、实体句柄。不存闭包，因此可以完整写入存档。
- 处理函数按效果类型注册；注册效果类型的模块是这类条目的唯一写者。
- 到期 tick 至少是下一个 tick，不允许零延迟，避免同一阶段内连锁（与 [ADR 0008](0008-module-collaboration.md) 的事件规则一致）。
- kernel 不替处理函数判断句柄是否有效；处理函数按"使用前校验"自行决定目标已失效时的行为（例如来源死亡后弹道仍然命中）。
- **冷却不走调度队列**：用组件字段 `readyAtTick` 表示。调度队列只用于一次性的延迟效果；周期性系统继续用 tick 取模降频。

### 实体关系
- **小队成员**：小队模块拥有的组件，记录小队 ID；小队本身是独立模块中的数据（[ADR 0009](0009-partial-ecs-boundary.md)）。
- **容纳**（驻防等）：契约组件 `ContainedIn`，记录容器句柄，由实现容纳的模块（例如驻防）唯一写入。被容纳的实体去掉 `InWorld` 标记，自动退出寻路、碰撞、渲染、索敌等以 `InWorld` 为条件的查询。容器被摧毁时，被容纳者弹出还是一同摧毁，由容器所属模块在伤亡清理阶段按内容数据处理。
- **挂载**：武器、炮塔等作为组件挂在建筑实体上，不拆成子实体；确有独立行为需要时再另写 ADR。
- 是否使用 bitecs 0.4 自带的关系功能，在 M1 核实 API 后决定；对外契约始终是 kernel 自己的接口。

## 后果

- 所有延迟行为可序列化、可复现，存档无需特殊处理计时器。
- `InWorld` 成为空间类查询的通用前提，新增空间系统必须带上它。
- 关系的种类增长时，需要评估是否统一到 kernel 的关系接口。
